# Voice choice — implementation plan (step 1 of the accounts design)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person can pick the outgoing and the incoming synthesized voice in the app — filter the list, listen to
samples — and the gateway speaks with the chosen voices.

**Architecture:** The gateway gains `GET /v1/voices` (the ElevenLabs account's voices, normalised and cached) and
accepts optional voice ids in `session.configure`. The app fetches the list itself over HTTP (Dart, one
implementation for both platforms), plays samples through an audio plugin, and passes the chosen ids through the
existing start map; both native hosts copy them into the configure message.

**Tech stack:** Node 22 + TypeScript + zod + `node --test` (gateway, protocol); Flutter + Riverpod (app); Swift
package `LiveBridgeAudio` (macOS host); C++17 `livebridge_core` + CTest (portable core, Windows host).

**Spec:** `docs/specs/2026-11-26-accounts-paid-service-voices-design.md` — sections "Voices" and "Order of work".
Only the own-gateway mode exists in this step; account and own-keys modes arrive in later steps.

## Global constraints

- A voice id matches `^[A-Za-z0-9]{10,40}$`. Anything else is refused, never forwarded to the provider.
- The voice list is cached for 10 minutes per key.
- Protocol version stays 1. A configure message without `voices` behaves exactly as today.
- Absent choice → the gateway's configured defaults (`ELEVENLABS_OWNER_VOICE_ID`, `ELEVENLABS_INCOMING_VOICE_ID`).
- Every new interface string exists in all four ARB files (uz, ru, tr, en); `flutter gen-l10n` regenerates the Dart.
- Before anything is shown to the owner: screenshots of the real app in uz, ru, tr and en, light and dark, macOS
  and Windows looks, with the picker open — checked for clipping and overlap.
- Dart is formatted with `dart format lib test` (page width 120 comes from `analysis_options.yaml`; never pass
  `--line-length`).
- Never run bare `python`; use `python3`.
- No key or token is printed, logged or committed. `.env`, `bench-out/` and `dist/` are never committed.
- Commit messages are the owner's: no `Co-Authored-By` and no tool attribution. Style of the log: `Area: what
  changed` (for example `Gateway: voice list route`).
- Work on a branch `voices` cut from `main`. Nothing is deployed and nothing is pushed without the owner saying so.
- macOS is built and verified first; the Windows host gets the same change and must pass the Windows workflow.

## Review focus

1. **Older gateway.** `GET /v1/voices` answers 404 → the picker says the gateway cannot list voices, both rows stay
   on "Default", and a session still starts. (Test in Task 6.)
2. **Provider key without the voices permission.** The gateway answers `502 voices_unavailable`; the app shows the
   message with Retry and does not block Start. (Tests in Tasks 4 and 8.)
3. **A saved voice the current account does not have.** The row shows the raw id instead of a name, the session
   reports the provider's `voice_not_found` in words, and "Default" is one click away. (Test in Task 8.)
4. **Many voices.** More than one provider page (100 per page) → all pages are returned and the list scrolls
   without building every row. (Tests in Tasks 4 and 8.)
5. **Samples.** Playing a second sample stops the first; closing the picker stops playback; a sample that fails to
   load returns the button to idle. (Tests in Tasks 7 and 8.)

enum VoicesFailure { unauthorized, unsupported, unavailable, network }
class VoicesException implements Exception { const VoicesException(this.failure); final VoicesFailure failure; }
abstract class VoicesClient { Future<List<Voice>> list({required String gatewayUrl, required String accessToken}); }

- Status mapping in `HttpVoicesClient`: 200 → the list (entries that fail `fromJson` are skipped); 401 →

  loaded from the saved settings like `translationModel`. Per-connection-mode storage comes with the connection
  modes in a later step — not now.
- No new package: `dart:io` is enough for one GET.
